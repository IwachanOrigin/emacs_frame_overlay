This package displays transparent PNG images over an Emacs frame
using a click-through native Windows overlay.

The overlay can be used like a background image without interfering
with normal mouse operations in Emacs.

This package has currently been tested only on Windows 11.

Only PNG image files are currently supported.

* Requirements
** Platform
- Windows 11 (tested)
- Native Windows Emacs 29.1 or later

** Build tools
- MSYS2 UCRT64
- g++
- CMake
- mingw32-make

** Image format
- PNG

* Installation
Using use-package is recommended.

When =frame-overlay-ensure-module= is called, the native dynamic module
is built automatically with CMake if it has not been built yet or if
the native source files have been updated.

#+begin_src emacs-lisp
  (use-package frame-overlay
    :vc (:url "https://github.com/IwachanOrigin/emacs_frame_overlay.git"
              :rev "v0.1.0"
              :lisp-dir "src/main/emacs")
    :demand t
    :config
    (frame-overlay-ensure-module))
#+end_src

** NOTE
Make sure the required build tools are available in Emacs's PATH.

#+begin_src emacs-lisp
  (executable-find "cmake")
  (executable-find "g++")
  (executable-find "mingw32-make")
#+end_src

* API
** Image Configuration
*** frame-overlay-scale
**** Usage
#+begin_src emacs-lisp
  (setq frame-overlay-scale 0.35)
#+end_src

**** Description
#+begin_example
Specifies the scale factor used to display PNG images.
1.0 is the actual size.

1.0  = 100%
0.5  = 50%
0.35 = 35%
0.25 = 25%

The default value is 1.0.
#+end_example

*** frame-overlay-position
**** Usage
#+begin_src emacs-lisp
  (setq frame-overlay-position 'bottom-right)
#+end_src

**** Description
#+begin_example
Specifies the position of the image within the frame.
The default value is `bottom-right`.
Allowed values:

top-left
top-right
bottom-left
bottom-right
center

Layout examples:
top-left                 top-right
+--------------------+   +--------------------+
| IMAGE              |   |              IMAGE |
|                    |   |                    |
|                    |   |                    |
+--------------------+   +--------------------+

bottom-left              bottom-right
+--------------------+   +--------------------+
|                    |   |                    |
|                    |   |                    |
| IMAGE              |   |              IMAGE |
+--------------------+   +--------------------+

center
+--------------------+
|                    |
|       IMAGE        |
|                    |
+--------------------+
#+end_example

*** frame-overlay-margin-x
**** Usage
#+begin_src emacs-lisp
  (setq frame-overlay-margin-x 24)
#+end_src

**** Description
#+begin_example
Specifies the horizontal margin in pixels.

For `top-left` and `bottom-left`, this is the distance from the left edge;
for `top-right` and `bottom-right`, this is the distance from the right edge.

The default value is `24`.
#+end_example

*** frame-overlay-margin-y
**** Usage
#+begin_src emacs-lisp
  (setq frame-overlay-margin-y 24)
#+end_src

**** Description
#+begin_example
Specifies the vertical margin in pixels.

For top alignment, this is the distance from the top edge;
for bottom alignment, it is the distance from the bottom edge.

The default value is `24`.
#+end_example

*** frame-overlay-image-alpha
**** Usage
#+begin_src emacs-lisp
  (setq frame-overlay-image-alpha 255)
#+end_src

**** Description
#+begin_example
Specifies the overall opacity (alpha) of the image.
The range is 0 to 255.

255 = Opaque
128 = About 50% opacity
96  = Faint
64  = Subtle
32  = Very faint
0   = Completely transparent

The apparent contrast of the overlay depends on the Emacs theme.
With a dark theme, dark images tend to be less noticeable while
bright images stand out. With a light theme, the opposite is generally true.

When an image is placed in the center of the editing area, a value
around 32 can keep it from becoming distracting while coding.

This value is independent of the alpha values already stored in the PNG.

Conceptually, the final alpha is calculated as:

PNG native alpha
    ×
frame-overlay-image-alpha

Therefore, transparent areas in the original PNG remain transparent.

The default value is 255.
#+end_example

*** frame-overlay-auto-sync
**** Usage
#+begin_src emacs-lisp
  (setq frame-overlay-auto-sync t)
#+end_src

**** Description
#+begin_example
Specifies whether the overlay automatically follows the Emacs frame
when the frame is moved or resized.

Set this to nil to disable automatic synchronization.

The current implementation uses an Emacs timer to periodically update
the overlay position rather than monitoring Win32 events directly.

The default value is t.
#+end_example

*** frame-overlay-sync-interval
**** Usage
#+begin_src emacs-lisp
  (setq frame-overlay-sync-interval 0.05)
#+end_src

**** Description
#+begin_example
Specifies the update interval for automatic tracking in seconds.

0.05 = 50 ms  = approx. 20 times/second
0.10 = 100 ms = approx. 10 times/second
0.25 = 250 ms = approx. 4 times/second

Setting a smaller value results in smoother tracking,
but increases the number of times the synchronization process is called.
The default value is `0.05`.
#+end_example

** Image operations
*** frame-overlay-show-file
**** Usage
#+begin_src emacs-lisp
  (frame-overlay-show-file "C:/path/to/test.png")
#+end_src

**** Description
#+begin_example
Displays the specified PNG image on the current Emacs frame.
Internally, the following processing takes place:
Load PNG
  ↓
Decode with WIC
  ↓
Convert to 32-bit PBGRA
  ↓
Resize at the specified scale
  ↓
UpdateLayeredWindow
  ↓
Display transparently on the frame

Any transparent areas in the PNG are rendered as transparent.
Additionally, since the overlay allows mouse interactions to pass through,
you can click on the image to interact with the Emacs interface behind it.
#+end_example

*** frame-overlay-refresh
**** Usage
#+begin_src emacs-lisp
  (frame-overlay-refresh)
#+end_src

**** Description
#+begin_example
Reloads and redisplays the currently displayed PNG image using the current settings.

frame-overlay-scale
frame-overlay-position
frame-overlay-margin-x
frame-overlay-margin-y
frame-overlay-image-alpha

If you change any of these settings and then call this function,
the changes will be reflected in the display.

Calling this function while a playlist is playing will not pause the playlist.
#+end_example

* Manual build
1) Change to the =src= directory.
2) Run =_build.sh= with the directory containing =emacs-module.h= as the first argument.
   
   Example:
   #+begin_src shell
     ./_build.sh <path/to/emacs/include>
   #+end_src

   For example, in my environment:
   #+begin_src shell
     ./_build.sh /c/software/msys2/ucrt64/local/emacs/include
   #+end_src

* Development

The release source code is located under =src/=.

#+begin_example
src/
├─ CMakeLists.txt
├─ _build.sh
├─ main/
│  ├─ module/
│  │  └─ frame_overlay_module.cpp
│  └─ emacs/
│      └─ frame-overlay.el
└─ test/
#+end_example

The native module can be built manually from the =src= directory:

#+begin_src shell
  ./_build.sh /c/path/to/emacs/include
#+end_src

The C++ module is loaded into the Emacs process as a DLL.
On Windows, a loaded DLL cannot be replaced safely while Emacs is
running. Restart Emacs before rebuilding a module that has already
been loaded.

The current release implementation is maintained under =src/=.
Files under =_prototype/= are historical experiments and are not
part of the release build.

* Prototype history

Early experiments are kept under =_prototype/= as historical snapshots.
They are not used by the release build.

** 01_transparent_square
Initial Win32 overlay prototype.

This prototype verified:

- frame-level overlay window creation
- transparent/semi-transparent rendering
- click-through mouse operation
- synchronization with the Emacs frame

** 02_transparent_image
Added PNG image support using Windows Imaging Component (WIC).

This prototype introduced:

- PNG loading
- per-pixel alpha
- image scaling
- configurable positioning and margins
- =UpdateLayeredWindow=

** 03_playlist_images
Added image playlist support.

This prototype introduced:

- automatic image switching
- playlist looping
- directory-based PNG playlists
- reusable overlay HWND

Reusing the overlay HWND instead of recreating it for every image
also fixed an issue where the overlay could disappear when focus
moved from Emacs to another application.

* Limitations
- Only native Windows builds of Emacs are supported.
- Only PNG images are currently supported.
- Overlay positioning is synchronized using an Emacs timer.
- A loaded dynamic module DLL cannot be safely overwritten in place.

  Restart Emacs before rebuilding a module that has already been loaded.
